# RTL Retiming Model

Учебный C++ проект для моделирования простой RTL-style pipeline-модели и проверки поведения после добавления задержки на один такт.

Проект имитирует ситуацию, близкую к retiming/verification: есть две модели одного вычисления:

- `CombinationModel` — комбинационная модель без задержки;
- `PipelinedModel` — pipeline-модель с задержкой на 1 такт.

Основная цель проекта — понять, как в RTL-моделях работают:

- такты (`cycle`);
- регистры;
- pipeline latency;
- `valid`-сигнал;
- `reset`;
- flush-такт;
- сравнение expected/actual outputs;
- mismatch diagnostics.

---

## Идея модели

Базовое вычисление:

```text
y = (a + b) * c
```

В `CombinationModel` результат появляется на том же такте:

```text
input на cycle N -> output на cycle N
```

В `PipelinedModel` результат появляется на следующем такте:

```text
input на cycle N -> output на cycle N + 1
```

Из-за этого сравнение моделей выполняется с учётом задержки:

```text
comb_outputs[i] сравнивается с pipe_outputs[i + 1]
```

---

## Поддерживаемые сигналы

Каждый входной такт содержит:

```text
reset valid a b c
```

Где:

- `reset` — сброс pipeline-регистров;
- `valid` — показывает, что входные данные на текущем такте настоящие;
- `a`, `b`, `c` — входные значения;
- `y` — выходное значение.

Если `reset = 1`, pipeline очищается, а выход считается невалидным:

```text
valid = 0
y = 0
```

---

## Что делает программа

Программа:

1. создаёт набор входных тактов;
2. прогоняет их через `CombinationModel`;
3. прогоняет их через `PipelinedModel`;
4. добавляет flush-такт для pipeline;
5. печатает таблицу по всем циклам;
6. сравнивает выходы моделей с учётом latency = 1;
7. учитывает reset на output-cycle;
8. выводит `Check: OK` или `Check: FAILED`;
9. при ошибке печатает mismatch report.

---

## Пример логики сравнения

Если на `cycle 1` был валидный вход:

```text
valid = 1, a = 1, b = 2, c = 3
```

то `CombinationModel` выдаст:

```text
cycle 1: valid = 1, y = 9
```

а `PipelinedModel` должен выдать этот результат на следующем такте:

```text
cycle 2: valid = 1, y = 9
```

Если на output-cycle активен `reset`, отложенный результат должен быть сброшен:

```text
expected valid = 0
expected y = 0
```

---

## Mismatch report

Если модели расходятся, программа выводит информацию об ошибке:

```text
Check: FAILED

Error in cycle - ...
On pipe cycle - ...
Expected valid - ...
Expected y - ...
Actual valid - ...
Actual y - ...
Reset occurred - true/false
Reason: ...
```

Это помогает понять:

- на каком input-cycle возникло расхождение;
- на каком pipe-cycle ожидался результат;
- какой результат ожидался;
- какой результат был получен;
- повлиял ли reset на output-cycle.

## Учебная цель

Этот проект не является полноценной RTL-моделью и не использует Verilog/SystemVerilog.

Его цель — на C++ понять базовые идеи, которые важны при работе с RTL-моделями:

- регистр хранит состояние между тактами;
- pipeline добавляет задержку;
- `valid` нужен для отличия настоящих данных от пустых;
- `reset` может очистить pipeline и удалить отложенный результат;
- модели нельзя всегда сравнивать на одном и том же cycle;
- при проверке важно выводить не только `FAILED`, но и подробную диагностику ошибки.
